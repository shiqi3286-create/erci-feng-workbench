# 开发文档 · 晴笺 AI 小说创作台

> 版本 v0.1.0（UI 骨架锁定） · 更新 2026-09-13

## 1. 产品定位

本地 AI 小说写作工具，面向 **10 万 ~ 100 万字** 长篇创作。

核心设计原则（开发任何功能前先对照）：

1. **数据主权优先**：全书文稿默认保存在用户本机，可离线使用；AI 是可选模块。
2. **上下文分片**：绝不把全书塞进模型上下文。采用「全局精简设定（常驻）＋ 语义检索按需加载 ＋ 近期章节 + 当前大纲」四级组装策略。
3. **AI 提取必须人工确认**：AI 自动识别的角色 / 伏笔只能进入「待确认」，不能直接改写设定库。
4. **校验按阶段跑**：人设 / 时间线 / 名词一致性检查按卷执行（写完一卷扫一次），不做逐章全量扫描，控制 token 成本。
5. **分文件存储**：一章一个正文文件，打开软件只加载当前章节，长篇不卡。

## 2. 创作工作流（工具应支持的闭环）

```
新建项目
  → 搭建世界观 / 人物 / 地点 / 物品 / 伏笔（可 AI 批量生成 + 人工审核）
  → 生成分卷大纲 → 章节大纲卡片（AI 生成 / 手动 / 混合）
  → 逐章创作：组装上下文 → AI 生成初稿 → 人工精修 → 标记伏笔/新角色 → 单章校验
  → 按卷一致性扫描（伏笔回收统计 / 名词统一 / 时间线更新）
  → 全文导出（TXT / MD / EPUB / 平台排版）
```

## 3. 页面与交互架构

### 3.1 页面导航

```
作品库 index.html ──→ 创作台 workspace.html
        │                  ↑
        └──────┬───────────┘
               ├── 大纲 outline.html（大纲卡片 → 生成正文跳创作台）
               ├── 设定库 world.html（引用设定 → 跳创作台）
               └── 模板·API template.html
```

### 3.2 创作台五区布局（已锁定，勿改结构）

| 区域 | 内容 | 对应代码 |
|---|---|---|
| 左栏 | 资源树：大纲 / 人物 / 伏笔 / 模板（tab 切换） | `workspace.js → renderSide()` |
| 中上 | AI 工具调用轨迹（读取设定→检索伏笔→组装上下文→生成→校验） | `renderTrace()` |
| 中间 | 正文输出区（AI 生成段落带 `.ai-mark` 标记，段落可点击选中） | `renderDoc()` |
| 中下 | 指令对话框（快捷指令 chip + 多行输入 + 发送） | `cmd-bar` 区块 |
| 右栏 | 上下文面板：本章小纲 / 人物 / 伏笔 / 建议 / 上下文预算 | `renderCtx()` |
| 底部 | 状态栏：保存状态 / 字数 / 修改次数 / 设定冲突 | `status-bar` |

### 3.3 关键交互约定

- 正文中 AI 生成段落使用 `.ai-mark`（下划线高亮），人工已确认段落去掉该 class。
- 段落点击 → `.sel` 高亮 → 指令区提示选中信息 → 后续指令默认作用于选中段落。
- 指令发送 → 更新 AI 轨迹状态 → 生成结果以 `.ai-mark` 段落追加到正文 → 字数 / token 预算联动更新。
- 所有未实现按钮以 `APP.toast('xxx（开发中）','')` 占位，禁止出现无反馈的僵尸按钮。

## 4. 技术架构

```
┌─────────────────────────────────────────────┐
│  UI 层（原生 HTML + CSS + JS，无框架）        │
│  index / workspace / outline / world / template
├─────────────────────────────────────────────┤
│  公共能力层                                  │
│  common.js（图标 / Toast / Modal）            │
│  ai.js（OpenAI 兼容流式客户端 / 渠道切换）     │
├─────────────────────────────────────────────┤
│  数据层                                      │
│  data.js（示例种子） + store.js（存储适配接口） │
│  当前：localStorage；未来：Tauri 文件命令       │
├─────────────────────────────────────────────┤
│  业务数据                                    │
│  项目 / 分卷 / 章节正文 / 设定 / 模板 / API     │
└─────────────────────────────────────────────┘
```

当前纯前端版本通过 `APP.store` 统一访问数据，使用 `localStorage` 持久化。后续 Windows/Tauri 封装时，保留同一接口，将实现替换为 Rust command 与磁盘目录读写即可。

**打包路线（推荐 Tauri）**：
- `tauri.conf.json` 指向本目录，`frontendDist` 设为项目根；
- 以 `read_chapter` / `write_chapter` 等 command 替换 `store.js` 的 localStorage 适配；
- 本地优先：无网可用，AI 模块为可选项。

## 5. 数据流示例：一次「生成初稿」

1. 用户在创作台点击「续写」或输入指令；
2. 前端组装请求：`当前章节大纲 + 上一章摘要 + 全局精简设定（≤1k tokens）+ 语义检索到的相关伏笔`；
3. 校验总 token 预算，超限则截断最旧内容；
4. 调用 API（当前渠道），失败自动切换备用渠道；
5. 流式返回 → 以 `.ai-mark` 段落渲染到正文 → 记录本次调用（模型 / tokens / 耗时）到右侧调用记录；
6. 生成完成后触发可选的后台动作：提示「新增伏笔待确认」「发现设定冲突」；
7. 用户人工精修后点击段落 → 「已确认」，移除 `.ai-mark`。

## 6. 当前存储适配与迁移

当前 `assets/js/data.js` 提供首屏示例种子，`assets/js/store.js` 在启动时从 `localStorage` 恢复数据；所有新增、编辑、删除、章节保存都会经由 `APP.store` 写回。存储键为 `novel-studio:data:v1`。

迁移到 Windows/Tauri 时：

1. 按 `docs/DATA-SCHEMA.md` 建立磁盘目录与 JSON / MD 文件；
2. 保留 `APP.store` 的业务方法与调用方，仅替换底层 `init / save / loadChapter / saveChapter` 实现；
3. 以 `chapters/volX/chNN.md` + `chNN.json` 保存正文与元数据；
4. 自动保存默认 60 秒，写失败必须 toast 明确报错；
5. 索引文件可重建，不作为唯一数据源。

## 7. AI 模块（后续开发要点）

- **API 客户端**：OpenAI 兼容格式，多渠道（主 / 备 / 自建中转），失败自动切换；本地统计 token 与费用。
- **模型分工**：轻量调用（润色 / 提取 / 校验）用小模型；长文生成 / 全卷总结用大模型。
- **提示词模板**：支持动态变量 `{{人物设定}} {{本章大纲}} {{选中文本}}`，发送前替换；参数独立配置（temperature / max tokens）。
- **安全边界**：只有用户主动触发（选中文本 / 点按钮）才发送；不主动上传全文；设定卡片是否随请求发送由用户开关控制。

## 9. 代码规范

- 原生 JS，无框架；数据驱动渲染：改 `window.DATA` 后调用重渲染函数；
- 样式只改 `style.css` 的设计令牌；新增组件类沿用现有命名；
- 图标一律使用 `common.js` 的 `APP.icon()` 内联 SVG；
- 按钮必须有真实反馈，禁止僵尸按钮；
- 不提交 API Key、真实稿件或本地数据快照；
- 页面级逻辑放对应 `assets/js/*.js`，公共能力放 `common.js`。

## 10. Windows 云端构建

本项目不要求开发者在本地安装 Rust、Visual Studio 或 Tauri CLI。GitHub Actions 使用 `windows-latest` 构建环境，执行 `npm install` 与 `npm run tauri build`，并上传 NSIS `.exe` 与 MSI `.msi` 安装包。

- 普通构建：推送到 `main` 或创建 Pull Request，触发 `.github/workflows/build-windows.yml`；
- 正式发布：推送 `v*` 标签，触发 `.github/workflows/release.yml` 并创建 GitHub Release；
- 仓库：`shiqi3286-create/erci-feng-workbench`；
- 本地浏览器模式保留 localStorage 兼容，不执行本地桌面编译。
