# 开发文档 · 晴笺 AI 小说创作台

> 版本 v0.4.0（托盘 / 图标 / 手动更新） · 更新 2026-09-14

## 1. 产品定位

本地 AI 小说写作工具，面向 **10 万 ~ 100 万字** 长篇创作。

核心设计原则（开发任何功能前先对照）：

1. **数据主权优先**：全书文稿默认保存在用户本机，可离线使用；AI 是可选模块。
2. **上下文分片**：绝不把全书塞进模型上下文。采用「全局精简设定（常驻）＋ 语义检索按需加载 ＋ 近期章节 + 当前大纲」四级组装策略。
3. **AI 提取必须人工确认**：AI 自动识别的角色 / 伏笔只能进入「待确认」，不能直接改写设定库。
4. **校验按阶段跑**：人设 / 时间线 / 名词一致性检查按卷执行（写完一卷扫一次），不做逐章全量扫描，控制 token 成本。
5. **分文件存储**：一章一个正文文件，打开软件只加载当前章节，长篇不卡。

## 2. 创作工作流（工具应支持的闭环）

```
新建项目
  → 搭建世界观 / 人物 / 地点 / 物品 / 伏笔（可 AI 批量生成 + 人工审核）
  → 生成分卷大纲 → 章节大纲卡片（AI 生成 / 手动 / 混合）
  → 逐章创作：组装上下文 → AI 生成初稿 → 人工精修 → 标记伏笔/新角色 → 单章校验
  → 按卷一致性扫描（伏笔回收统计 / 名词统一 / 时间线更新）
  → 全文导出（TXT / MD / EPUB / 平台排版）
```

## 3. 页面与交互架构

### 3.1 页面导航

```
作品库 index.html ──→ 创作台 workspace.html
        │                  ↑
        └──────┬───────────┘
               ├── 大纲 outline.html（大纲卡片 → 生成正文跳创作台）
               ├── 设定库 world.html（引用设定 → 跳创作台）
               └── 模板·API template.html
```

### 3.2 创作台五区布局（已锁定，勿改结构）

| 区域 | 内容 | 对应代码 |
|---|---|---|
| 左栏 | 资源树：大纲 / 人物 / 伏笔 / 模板（tab 切换） | `workspace.js → renderSide()` |
| 中上 | AI 工具调用轨迹（读取设定→检索伏笔→组装上下文→生成→校验） | `renderTrace()` |
| 中间 | 正文输出区（AI 生成段落带 `.ai-mark` 标记，段落可点击选中） | `renderDoc()` |
| 中下 | 指令对话框（快捷指令 chip + 多行输入 + 发送） | `cmd-bar` 区块 |
| 右栏 | 上下文面板：本章小纲 / 人物 / 伏笔 / 建议 / 上下文预算 | `renderCtx()` |
| 底部 | 状态栏：保存状态 / 字数 / 修改次数 / 设定冲突 | `status-bar` |

### 3.3 关键交互约定

- 正文中 AI 生成段落使用 `.ai-mark`（下划线高亮），人工已确认段落去掉该 class。
- 段落点击 → `.sel` 高亮 → 指令区提示选中信息 → 后续指令默认作用于选中段落。
- 指令发送 → 更新 AI 轨迹状态 → 生成结果以 `.ai-mark` 段落追加到正文 → 字数 / token 预算联动更新。
- 所有未实现按钮以 `APP.toast('xxx（开发中）','')` 占位，禁止出现无反馈的僵尸按钮。

### 3.4 桌面集成（托盘 / 更新 / 安装器，v0.4.0）

- **系统托盘**（`lib.rs` setup，`tray-icon` feature）：
  - 左键单击切换主窗口显隐；右键菜单：显示主窗口 / 检查更新 / 退出；
  - 关闭主窗口默认最小化到托盘（`CloseRequested` 被拦截），退出只走托盘菜单；
  - 托盘图标复用 `bundle.icon` 的默认窗口图标。
- **手动检查更新**（已决策不使用 tauri-plugin-updater 自动更新，避免签名密钥依赖）：

  - 浏览器模式：检查更新直接打开发布页；
  - 相关命令：`app_version`、`open_release_page`（Windows 下 `cmd /c start` + CREATE_NO_WINDOW）。
- **应用图标**：源图 `src-tauri/icons/app-icon-source.png`（画图模型生成，暖阳纸笔主题）；
  由 `scripts/gen-icons.mjs`（纯 Node + 内置 zlib，零第三方依赖）生成多尺寸 `icon.ico`（16–256px，256 用 PNG 条目、其余 32bit BMP）与 PNG；
  重新生成：`node scripts/gen-icons.mjs src-tauri/icons/app-icon-source.png src-tauri/icons`。
- **安装向导中文化**：NSIS 显式 `languages: ["SimpChinese","TradChinese","English"]` + `displayLanguageSelector`；MSI（WiX）`language: ["zh-CN"]`。

## 4. 技术架构

```
┌─────────────────────────────────────────────┐
│  UI 层（原生 HTML + CSS + JS，无框架）        │
│  index / workspace / outline / world / template
├─────────────────────────────────────────────┤
│  公共能力层                                  │
│  common.js（图标 / Toast / Modal / 全局搜索）  │
│  ai.js（OpenAI 兼容流式客户端 / 渠道切换）     │
│  updater.js（手动检查更新 / 托盘事件监听）     │
├─────────────────────────────────────────────┤
│  数据层                                      │
│  data.js（示例种子） + store.js（存储适配接口） │
│  当前：localStorage；未来：Tauri 文件命令       │
├─────────────────────────────────────────────┤
│  业务数据                                    │
│  项目 / 分卷 / 章节正文 / 设定 / 模板 / API     │
└─────────────────────────────────────────────┘
```

当前纯前端版本通过 `APP.store` 统一访问数据，浏览器模式使用 `localStorage`；Tauri 模式保留全量 `store.json` 作为备份/迁移镜像，并开始将当前章节写入独立的 Markdown + JSON bundle。后续章节文件将成为长篇正文的主要数据源。

**打包路线（Tauri 2）**：
- `tauri.conf.json` 指向生成的 `dist/` 前端资源；
- 章节正文通过 `load_chapter_bundle` / `save_chapter_bundle` 等 Rust command 读写；
- `store.json` 仅用于全量备份、旧数据迁移和兼容恢复；
- 本地优先：无网可用，AI 模块为可选项。

## 5. 数据流示例：一次「生成初稿」

1. 用户在创作台点击「续写」或输入指令；
2. 前端组装请求：`当前章节大纲 + 上一章摘要 + 全局精简设定（≤1k tokens）+ 语义检索到的相关伏笔`；
3. 校验总 token 预算，超限则截断最旧内容；
4. 调用 API（当前渠道），失败自动切换备用渠道；
5. 流式返回 → 以 `.ai-mark` 段落渲染到正文 → 记录本次调用（模型 / tokens / 耗时）到右侧调用记录；
6. 生成完成后触发可选的后台动作：提示「新增伏笔待确认」「发现设定冲突」；
7. 用户人工精修后点击段落 → 「已确认」，移除 `.ai-mark`。

## 6. 当前存储适配与迁移

当前 `assets/js/data.js` 提供首屏示例种子，`assets/js/store.js` 在启动时恢复数据。浏览器模式使用 `localStorage`；Tauri 模式在保留全量 `store.json` 兼容镜像的同时，当前章节通过 `load_chapter_bundle` / `save_chapter_bundle` 写入独立的 `.md` 正文与 `.json` 元数据文件。业务方法仍统一经由 `APP.store`，页面不直接调用存储实现。

章节 bundle 的正文与元数据分离：`.md` 保存可读正文，`.json` 保存段落 `cls`（包括 `ai-mark`）、字数、修改次数、更新时间、状态和快照指针。浏览器模式使用章节专用 localStorage key 模拟同一接口，因此 Edge 预览不依赖 Tauri。

迁移与保存约定：

1. 旧版 `projectData + beat.paras` 数据继续保留并可直接读取；章节 bundle 缺失时回退内存数据；
2. Tauri 章节写入使用 Rust 临时文件 + rename，避免单文件写入中断留下半截 JSON/Markdown；
3. 全量 `store.json` 仍用于手动备份、旧版本迁移和缓存恢复，不作为后续百万字正文的最终组织形式；
4. 自动保存默认 60 秒，章节切换前等待当前章节写入队列；写失败必须 toast 明确报错；
5. 下一阶段继续将设定、大纲、模板、API 和索引迁移为独立文件，并补全全项目逐章迁移器。

## 7. AI 模块（后续开发要点）

- **API 客户端**：OpenAI 兼容格式，多渠道（主 / 备 / 自建中转），失败自动切换；本地统计 token 与费用。
- **模型分工**：轻量调用（润色 / 提取 / 校验）用小模型；长文生成 / 全卷总结用大模型。
- **提示词模板**：支持动态变量 `{{人物设定}} {{本章大纲}} {{选中文本}}`，发送前替换；参数独立配置（temperature / max tokens）。
- **安全边界**：只有用户主动触发（选中文本 / 点按钮）才发送；不主动上传全文；设定卡片是否随请求发送由用户开关控制。

## 9. 代码规范

- 原生 JS，无框架；数据驱动渲染：改 `window.DATA` 后调用重渲染函数；
- 样式只改 `style.css` 的设计令牌；新增组件类沿用现有命名；
- 图标一律使用 `common.js` 的 `APP.icon()` 内联 SVG；
- 按钮必须有真实反馈，禁止僵尸按钮；
- 不提交 API Key、真实稿件或本地数据快照；
- 页面级逻辑放对应 `assets/js/*.js`，公共能力放 `common.js`。

## 11. 需求确认（2026-09-14 · 已对齐 · 待开发）

**已定决策**：

### 11.1 API 配置优化（写作 / 画图分离）

- 渠道增加 `type` 字段：`text`（写作）/ `image`（画图）；「模板·API」页分区块展示两类渠道，各自独立默认渠道（`defaultApi` / `defaultImageApi`）、启停、可用计数，互不影响。
- 画图请求：先支持 OpenAI 兼容 `POST /v1/images/generations`（模型 / 提示词 / 尺寸比例 / 数量）；渠道配置增加「接口格式」字段（默认 OpenAI 兼容），后续可扩展火山方舟等特殊格式，不影响写作链路。
- 「拉取模型」：渠道编辑中以接口地址 + Key 请求模型列表（`GET /v1/models`）填充下拉；服务商不支持时提示原因，允许手填。
- 「测试模型」：发最小真实请求验证连通性（文本走短 chat/completions，画图走最小生成请求），显示成功/失败、耗时、具体报错（HTTP 状态码 + 错误信息）。
- 创作入口：创作台选中段落后「生成插图」；设定库人物卡片「生成头像」；作品封面生成后置。
- 画图提示词模板：模板支持类型/分组，负责把场景描写转成带风格 / 镜头 / 氛围的视觉提示词。
- 图片存储：localStorage 阶段以 dataURL 存章节附件 + 提供下载按钮；Tauri 落盘阶段改磁盘存储。

### 11.2 主页优化（作品库 index.html）

- 搜索 + 筛选：按状态（连载中 / 草稿 / 完结）、题材类型、排序（最近更新 / 字数 / 进度）。
- 作品卡片增强：封面图（复用 `assets/img/cover-*.jpg`）、字数进度条、章节数、上次写到的位置、卡片内快捷入口（继续写 / 大纲 / 导出）。
- 统计卡升级：静态数字 → 本周写作趋势、连续写作天数等动态指标。
- 空状态引导：无作品时给出「从世界观开始 / 直接开写」的创建引导。
- 备份 / 恢复按钮从主页移入个人信息页。

### 11.3 个人信息页面（profile.html，右上角头像进入）

- 基础资料：昵称（问候语使用，不写死「阿晴」）、头像（上传 / 画图模型生成）、个性签名。
- 写作统计：累计字数、写作天数、连续写作天数、AI 生成占比、各作品字数分布。
- 创作目标：日更字数目标、作品完结目标、进度打卡。
- 偏好设置：编辑器字体 / 字号 / 行距、自动保存间隔、AI 自动发送开关（自模板页迁入）、默认写作/画图渠道。

- 平台发布偏好：番茄小说等平台的导出格式（段落缩进、章节标题、正文格式）。
